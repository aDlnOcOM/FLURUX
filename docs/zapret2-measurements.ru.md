# zapret2 в FLURUX. Что видно в сети и что измеряют тесты

## Можно ли определить наименее заметный профиль?

По результатам клиентского теста определить это нельзя. Успешный запрос показывает, что сайт ответил с этой сети в момент измерения. При одинаковом ответе клиент не может различить соединение, которое классификатор пропустил после распознавания, и соединение, которое он не распознал. Для оценки вероятности распознавания нужны независимые данные о решениях наблюдателя. FLURUX таких данных не получает.

| Признак | Что видит наблюдатель на участке связи |
| --- | --- |
| Адреса и транспорт | Внешние IP-адреса соединения, транспорт и его открытые заголовки. При прямом соединении с zapret2 назначением остаётся IP сайта или его CDN. |
| Имя сайта | Наблюдатель может увидеть имя в открытом DNS или в обычном TLS ClientHello. При согласованном ECH внутренний ClientHello зашифрован. Внешний IP остаётся видимым, а один адрес CDN может обслуживать много сайтов. |
| Характер обмена | Даже при шифровании TLS доступны размеры, направления и интервалы между пакетами. Эти признаки сами по себе не дают клиенту сведений о решении классификатора. |
| Точка наблюдения | Исследование ТСПУ 2022 года основано на измерениях из конкретных сетей в конкретный период. Переносить его результаты на любого оператора и текущую конфигурацию оборудования нельзя. |

Сведения об открытых и зашифрованных полях и пределах анализа приведены в [RFC 9849, §1](https://www.rfc-editor.org/rfc/rfc9849.html#section-1) и [RFC 8446, приложение E.3](https://www.rfc-editor.org/rfc/rfc8446.html#appendix-E.3). Данные о российской инфраструктуре и методике измерений приведены в [исследовании Xue и соавторов, IMC 2022](https://ensa.fi/papers/tspu-imc22.pdf).

## Из чего состоят 60 профилей

| Параметр | Варианты |
| --- | --- |
| Обработка | Разделение TLS или перестановка TLS. Для каждого из этих двух методов есть вариант с обработкой QUIC и вариант только для TCP. |
| Семейство адресов | IPv4, IPv6, оба семейства. |
| Порты назначения | 443, 8443, 9443, набор 443 и 8443, набор 443, 8443 и 9443. |

Получаются 60 сочетаний четырёх режимов обработки, трёх IP-фильтров и пяти наборов портов. Включение 8443 имеет смысл для сайта, который действительно слушает этот порт. Изменение фильтра в FLURUX не меняет порт сервера. Для домена на 443 несколько строк каталога могут показать одинаковый результат. Вариант IPv6 требует доступного IPv6-маршрута и соответствующего адреса сайта.

## Как сравнить на своём подключении

1. Откройте **Тесты**, введите адрес нужного сайта вместе с портом. Файл для замера скорости и сервер STUN можно заменить своими или оставить пустыми.
2. Проверьте **Системное подключение** и сравните с **Выбранный профиль zapret2** или **Все 60 профилей zapret2** на тех же целях. Временный сеанс использует тестовые домены и учитывает исключения. При проверке активного сеанса действуют его собственные списки.
3. Для оценки WEB смотрите ответ HTTP и время до первого байта. При проверке zapret2 перенаправление показывается отдельно, чтобы ответ другого сайта не попал в результаты профиля. Один ответ 200 не подтверждает корректность содержимого страницы.
4. VIDEO показывает скорость короткой загрузки объёмом до 1 МиБ. При ответе меньше 256 КиБ оценка отсутствует. Метка HD означает, что эта проба достигла 5 Мбит/с. Плеер может использовать другой CDN и требовать другую скорость.
5. У пинга указан тип измерения. ICMP относится к системному пути до сайта. GAME оценивается по четырём обменам UDP с выбранным STUN-сервером. Для положительной оценки нужны медиана до 80 мс, среднее изменение соседних задержек до 20 мс и четыре ответа. Это ориентир для интерактивного UDP. Игровой сервер может находиться в другой сети. Профиль zapret2 для HTTPS и QUIC не обрабатывает STUN, поэтому GAME в его строке остаётся пустым.
6. Выберите строку, чтобы прочитать причину пропуска или детали измерения. Для сравнения в другое время сохраните CSV. Смена сети, нагрузка, DNS и состояние сайта могут повлиять на результаты. Методика OONI отдельно разбирает ложные срабатывания при диагностике доступности. [OONI Web Connectivity](https://ooni.org/nettest/web-connectivity/)

**Что означают прочерки.** Отсутствие измерения, несовместимый транспорт или неподходящая цель. Работу HTTP/3 клиент подтверждает только при успешном запросе HTTP/3 средствами системного curl. Работа обычного HTTPS сама по себе её не подтверждает.
